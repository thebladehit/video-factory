# Підпроєкт 2 «Редактор + рендер» — специфікація

- **Дата:** 2026-10-20
- **Статус:** погоджено в обговоренні, очікує перегляду
- **Базова специфікація:** `docs/specs/2026-10-20-video-factory-design.md` (§2.1 рушій A, §5 дані, §5.1 TimelineDoc, §6.3 редактор, §6.5 рендер, §11 тести)
- **Бібліотека:** `docs/specs/2026-10-20-subproject-1-library.md` (гілка `feat/subproject-1-library`; ця гілка `feat/subproject-2-editor` відгалужена від неї)
- **Прототип:** `prototypes/editor-demos` (CanvasPreview, Timeline, ffmpegCommand — уроки, не код продукту)

## 1. Мета

У редакторі можна скласти ролик із файлів бібліотеки (або перетягнутих з ОС), змонтувати його — рух, трім, розрізання, видалення, ефекти, гучність — з canvas-прев'ю, що **збігається з результатом за таймінгом** (±1 кадр), і отримати MP4 у бібліотеці. Формати 9:16 і 16:9.

### Рішення власника (з обговорення)
| Питання | Рішення |
|---|---|
| Звук відео | Як у редакторах: під відео — зв'язаний аудіокліп із хвилею на доріжці «Звук відео»; можна видалити окремо або поставити гучність 0–200 %; «Від'єднати звук» |
| Ефекти | Пресети з розумними замовчуваннями; **фото автоматично отримує Ken Burns**; усі параметри ефектів редагуються вручну в інспекторі |
| Видалення файлу, що є в проєктах | Модалка-попередження зі списком проєктів; після видалення — червона заглушка на таймлайні (таймінг не зсувається), рендер блокується до заміни/прибирання |
| Рендер | Одна кнопка: «Фінал 1080p» або «Чернетка 720p»; H.264 + AAC, 30 кадр/с; прогрес і скасування в редакторі; історія рендерів проєкту |
| Спільність прев'ю й рендеру | **Спільне ядро `packages/timeline`**: операції, `evaluate(doc, t)`, закони ефектів (число для canvas + вираз для ffmpeg з одного опису) |

## 2. Дані (міграція 0004)

**`projects`**: `id`, `user_id`, `title`, `format` (`9:16` \| `16:9`), `fps int default 30`, `timeline jsonb`, `timeline_version int default 1`, `asset_ids uuid[] default '{}'` (GIN; сервер перераховує з таймлайну при кожному збереженні), `status text default 'draft'` (`draft|ready|published`), `topic text`, `base_language text default 'uk'`, `languages text[] default '{uk}'`, `created_at`, `updated_at`. Індекс `(user_id, updated_at)`.

**`renders`**: `id`, `user_id`, `project_id` (cascade), `preset` (`final|draft`), `language text null`, `timeline_snapshot jsonb`, `timeline_version int`, `status` (дзеркало задачі: `queued|running|done|failed|cancelled`), `job_id`, `output_asset_id uuid` (= id рендеру після створення asset; `on delete set null`), `error text`, `created_at`, `finished_at`.

**`assets`** + `has_audio boolean null` (null — ще не проаналізовано), `peaks_key text null`.
- Піки хвилі: `u/{userId}/assets/{assetId}/peaks.bin` — `Uint8` (0–255, максимум |амплітуди| моно) по 100 значень на секунду; ~6 КБ/хв.
- `asset.process` для відео й аудіо визначає `has_audio` (ffprobe) і за наявності звуку пише піки (ffmpeg → `f32le` моно 8 кГц → агрегація в Node).
- Для наявних `ready`-файлів відео/аудіо з `has_audio is null` — на старті API одноразово ставиться задача **`asset.analyze { assetId }`** (те саме без мініатюри); також запускається при `projects.get`, якщо такий файл є в проєкті.

## 3. Ядро `packages/timeline` (чистий TS; без DOM, ffmpeg, БД)

### 3.1 Схема (у `packages/shared`, лишається `schemaVersion: 1`, лише необов'язкові поля)
- `MediaClip` + `volume?: number` (0–2; звук самого відео, коли він не винесений у зв'язаний кліп; за замовчуванням 0 для відео зі зв'язаним аудіо) + `linkId?: string`.
- `AudioClip` + `linkId?: string`.
- Audio track `role` + `'original'` («Звук відео»).
- `Effect` — розрізнений union з явними параметрами (числа, за замовчуванням у дужках):
  - `kenburns`: `fromScale` (1), `toScale` (1.15), `fromX`, `fromY`, `toX`, `toY` (0.5; точка фокусу в частках кадру 0..1);
  - `zoom`: `scale` (1.2), `x`, `y` (0.5);
  - `fade`: `in` (0.3), `out` (0) — секунди;
  - `xfade`: `duration` (0.5) — перекриття з попереднім кліпом цієї доріжки, протягом якого кліп проявляється.
- Документ із бази проходить `normalizeDoc` (заповнення замовчувань; старі `params: {}` → дефолти), тож старі документи читаються.

### 3.2 Операції (чисті `doc → doc`)
- Усі часи (`start`, `duration`, `in`) округлюються до кадру `1/fps`; мінімальна тривалість — 1 кадр.
- `addClip(doc, asset, { trackId?, at })`: фото → 5 с + `kenburns`; відео → повна довжина; якщо `has_audio` — зв'язаний `AudioClip` на доріжці `original` з тим самим `start/in/duration` і `linkId`; аудіо → доріжка `music`. Доріжки створюються автоматично (порядок: відео-доріжки, `original`, `music`).
- `moveClip(id, start, trackId?)`, `trimStart(id, t)`, `trimEnd(id, t)`: межі — `[0, тривалість джерела]` для відео/аудіо (фото — без меж), кліп не лівіше 0. Зв'язаний кліп змінюється синхронно.
- `splitAt(id, t)` (розрізає й зв'язаного партнера; нові частини отримують новий спільний `linkId`), `deleteClips(ids)` (видалення відео видаляє й зв'язане аудіо; видалення аудіо — лише аудіо, відео лишається з `volume` 0), `unlink(linkId)`, `setVolume`, `setEffect`, `removeEffect`, `setFormat(format)` (міняє `width/height`; кліпи лишаються, бо всі повнокадрові).
- `snap(value, targets, { tolerancePx: 8, pxPerSec })`; цілі — краї всіх кліпів (крім тих, що рухаються), плейхед, 0.
- **Перекриття** на одній доріжці дозволене лише як перехід: `xfade.duration` наступного кліпу = довжина перекриття. Звичайний рух на зайняте місце ставить кліп впритул до найближчого вільного краю.
- `docDuration(doc)` = кінець останнього кліпу.

### 3.3 Обчислення
- `evaluate(doc, t) → Layer[]`, `Layer = { clipId, assetId, kind: 'image'|'video', sourceTime, alpha, scale, cx, cy, fit }` — у порядку шарів (нижня відео-доріжка перша). `alpha` враховує `fade` і `xfade`; `scale/cx/cy` — `kenburns`/`zoom`.
- `audioPlan(doc) → AudioItem[]`, `AudioItem = { clipId, assetId, start, in, duration, volume, fadeIn, fadeOut }` — аудіокліпи + звук відео-кліпів з `volume > 0`; кліпи з `missing` асетами пропускаються лише в прев'ю.
- **Закони ефектів:** кожен описано один раз як `{ at(p: number): number; expr(p: string): string }` (`p` — прогрес 0..1 у кліпі), напр. `lerp(a, b)` → `at = a+(b-a)*p`, `expr = "a+(b-a)*(p)"`. `evaluate` використовує `at`, `compileFfmpeg` — `expr`.
- `drawFrame(ctx, doc, layers, sources)` — малює чорне полотно і шари (cover/contain, масштаб навколо точки фокусу, `globalAlpha`); `ctx` — мінімальний інтерфейс 2D-контексту, працює з браузерним canvas і з `@napi-rs/canvas`.

## 4. API

Модулі — сервіс (функції над `deps`) + тонкий роутер. Усі запити фільтруються за `userId`; чужий id = `NOT_FOUND`.

| Процедура | Поведінка |
|---|---|
| `projects.list()` | картки: назва, формат, тривалість, мініатюра (останній рендер або мініатюра першого візуального кліпу), `updatedAt`; сортування за `updatedAt desc` |
| `projects.create({ title, format })` | порожній таймлайн формату |
| `projects.get({ id })` | `timeline` (нормалізований), `version`, `assets: Record<assetId, EditorAsset>`; `EditorAsset` = `{ kind, status, url, thumbUrl, peaksUrl, width, height, durationMs, hasAudio, title }` або `{ missing: true }` |
| `projects.assets({ ids })` | ті самі `EditorAsset` (оновлення URL до закінчення 1 год і після завантаження файлу з ОС) |
| `projects.save({ id, timeline, baseVersion })` | Zod + `normalizeDoc` → `UPDATE … WHERE timeline_version = baseVersion` → `version+1`, перерахунок `asset_ids`, `format` з `width/height`; інакше `CONFLICT` |
| `projects.rename({ id, title })`, `projects.duplicate({ id })`, `projects.delete({ id })` | delete з підтвердженням у UI; рендери-asset у бібліотеці лишаються |
| `renders.start({ projectId, preset, version })` | версія має збігатися з поточною (`CONFLICT` інакше); перевірки: таймлайн не порожній, усі файли існують і `ready` — інакше `VALIDATION` з `details: { clipIds }`; `renders` (`queued`, знімок) → задача `render`. Asset результату має **id = id рендеру** і створюється задачею після ffmpeg (повтор не дублює; до кінця рендеру в бібліотеці немає «порожнього» файлу) |
| `renders.list({ projectId })` | історія з прогресом задачі, `downloadUrl` готових |
| `renders.cancel({ id })` | скасування задачі |
| `assets.usage({ id })` | `[{ projectId, title }]` — для модалки видалення |

## 5. Рендер

### 5.1 `packages/render`
```ts
interface Renderer {
  render(input: { doc: TimelineDoc; sources: Map<string, SourceInfo>; preset: 'final' | 'draft'; outPath: string; workDir: string },
         ctx: { signal: AbortSignal; onProgress(pct: number): void }): Promise<void>;
}
```
`FfmpegRenderer` — `compileFfmpeg` + запуск через `@vf/media` `run` (з `-progress pipe:1` і читанням stdout потоком).

**`compileFfmpeg(doc, { preset, sources, language })` → `{ args, filterScript, durationSec, width, height }`** — чиста функція (`sources`: шлях, тип, розміри, `hasAudio`):
- Розмір виходу: `final` = розмір документа; `draft` = довша сторона 1280 (720×1280 / 1280×720), усі координати масштабуються.
- **Відео:** `color=black:s=WxH:r=fps:d=T[base]`. Для кожного шару: вхід (відео `-ss in -t dur -i`; фото `-loop 1 -framerate fps -t dur -i`) → `fps`, `scale` cover/contain з урахуванням `scale/cx/cy` через вирази законів (`scale … eval=frame` + `crop` з виразними `x/y`; **не `zoompan`** — тремтить) → `format=yuva420p`, альфа з `fade`/`xfade` (`fade=…:alpha=1`) → `setpts=PTS-STARTPTS+start/TB` → `overlay=eof_action=pass:enable='between(t,start,end)'`.
- **Аудіо:** для кожного `AudioItem` — вхід `-ss in -t dur` → `aformat`, `volume`, `afade` in/out, `adelay=start_ms:all=1`; разом з `anullsrc` на всю тривалість → `amix=inputs=N:normalize=0:duration=first`.
- Вихід: `libx264` (`final`: `-preset medium -crf 20`; `draft`: `-preset veryfast -crf 26`), `-pix_fmt yuv420p`, `-r fps`, AAC 192k / 48 кГц, `-t T`, `-movflags +faststart`.
- Граф пишеться у файл і передається `-filter_complex_script` (довгі проєкти не влазять у командний рядок).
- `language` зараз не використовується (точка розширення для підпроєкту 3: озвучка/субтитри мови).

### 5.2 Задача `render { renderId }` (concurrency 1)
1. Рендер і знімок з `renders`; якщо `output_asset_id` уже `ready` — нічого не робити (ідемпотентність).
2. Тимчасова тека; кожен потрібний asset завантажується зі сховища один раз.
3. `Renderer.render` → прогрес `out_time / T` (0–95 %) через `ctx.progress`.
4. `out.mp4` → put у ключ asset → asset (id = renderId, `processing`; insert … on conflict do nothing) → задача `asset.process` (мініатюра, метадані, `has_audio`, піки) → прогрес 100 %.
5. Статус `renders` синхронізується зі статусом задачі (як `generations`).
- Тимчасова тека — у `finally`. Таймаут ffmpeg — `max(10 хв, 5 × T)`. Скасування вбиває ffmpeg (`signal`); asset ще не створено, тож прибирати нічого (крім об'єкта S3, якщо встиг завантажитись). Після рестарту — наявне відновлення черги (`running` → `failed` «Перервано перезапуском», «Повторити» = новий запуск того ж рендеру).
- Назва asset: «{назва проєкту} — {дата час}», `source='rendered'`.

## 6. Інтерфейс (apps/web)

### 6.1 Маршрути
- `/` — «Проєкти» (пункт меню вже веде сюди; замість `ComingSoon`): сітка карток, «Новий проєкт» (діалог: назва, формат 9:16 / 16:9), меню картки: перейменувати, дублювати, видалити (з підтвердженням).
- `/projects/$id` — редактор.

### 6.2 Розкладка редактора (десктоп)
```
┌ верх: назва · 9:16/16:9 · ↶ ↷ · стан збереження · [Рендер ▾]  ┐
├ бібліотека        ├──────── прев'ю ────────┤ інспектор кліпу   │
│ (пошук, фільтр    │ canvas + ▶ / час / тр. │ (гучність, ефекти, │
│  типу, тягнути)   │                        │  «Від'єднати звук»)│
├──────────── таймлайн (лінійка, доріжки, зум, плейхед) ─────────┤
└──────────────── історія рендерів (згортається) ────────────────┘
```

### 6.3 Стор
- Zustand: `doc` (під zundo, ліміт 100 кроків) + окремий UI-стан (вибір, плейхед, зум, програвання) — поза історією.
- Жести (рух, трім, ручка переходу) — **один крок історії**: `pause()` на `pointerdown`, проміжні оновлення, `resume()` + фіксація на `pointerup`.

### 6.4 Таймлайн
- Доріжки (зверху вниз на екрані): відео-доріжки (верхня перекриває нижню), «Звук відео», «Музика»; «+ доріжка відео».
- Рух (зокрема між доріжками одного типу), трім за краї, снепінг (8 px, до країв і плейхеда; підсвічується лінією), зум (Ctrl/⌘ + колесо, повзунок), прокрутка, клік по лінійці — перемотка.
- Кліпи: фото/відео — смуга мініатюр; аудіо — хвиля з піків; зв'язані кліпи виділяються разом; видалений файл — червона заглушка «файл видалено»; файл, що завантажується, — мітка з прогресом.
- Ручка переходу на стику двох кліпів однієї доріжки: тягнеш — змінюється перекриття (`xfade`).
- Клавіші: S — розрізати під плейхедом, Del/Backspace — видалити, Space — play/pause, ⌘Z / ⇧⌘Z — undo/redo, ←/→ — кадр, ⇧←/⇧→ — 1 с.

### 6.5 Прев'ю (`PreviewEngine`)
- Canvas: внутрішній розмір = відображений × `devicePixelRatio`, `imageSmoothingQuality='high'`; кадр = `drawFrame(evaluate(doc, t))`.
- Фото — `HTMLImageElement`; відео — прихований `<video muted>` на кожен кліп (`crossOrigin='anonymous'`); пауза/перемотка — точний seek і перемальовування після `seeked`.
- Звук — Web Audio: на кожен `AudioItem` прихований `<audio>` (`crossOrigin='anonymous'`) → `MediaElementAudioSourceNode` → `GainNode` (гучність + fade за тими ж формулами) → вихід. RustFS отримує CORS-правило для origin веб-додатку (інакше Web Audio з чужого origin дає тишу).
- Годинник програвання — `AudioContext.currentTime`; відео й аудіоелементи підтягуються, якщо розійшлися > 0,15 с.
- Файл, який браузер не може декодувати, — заглушка «браузер не може показати цей файл» (рендер працює).
- `PreviewEngine` — інтерфейс (`attach(canvas)`, `setDoc`, `seek`, `play`, `pause`, `onTime`), щоб пізніше замінити на Remotion Player.

### 6.6 Drag & drop
- З панелі бібліотеки на доріжку → `addClip` у місці відпускання (зі снепінгом).
- З ОС на таймлайн → файл іде через глобальний `UploadProvider` (`addFiles` повертає `assetId` для кожного файлу); кліп з'являється одразу з локальним `blob:`-URL і тривалістю, яку браузер прочитав з файлу (`loadedmetadata`; фото — 5 с). Коли asset `ready` (за `jobs.feed`) — URL замінюється на серверний; для відео з `has_audio` додається зв'язаний аудіокліп (якщо відео-кліп ще існує). Поки є незавантажені — «Рендер» недоступний із підказкою. Drop з ОС поза таймлайном працює як раніше (лише в бібліотеку).

### 6.7 Автозбереження
- Debounce 1,5 с після останньої зміни; також `visibilitychange`/вихід зі сторінки (з `beforeunload`-попередженням, якщо збереження не вдалося).
- Індикатор: «Збережено» / «Зберігаю…» / «Не збережено — повторити».
- `CONFLICT` → модалка «Проєкт змінено в іншій вкладці»: «Перезавантажити» (втрата локальних змін) або «Перезаписати моєю версією» (повторне збереження з актуальною `baseVersion`).

### 6.8 Рендер і історія
- «Рендер ▾» → «Фінал 1080p» / «Чернетка 720p» → спершу збереження → `renders.start`.
- Історія: статус, прогрес (за `jobs.feed`), «Скасувати», для готових — тривалість, «Завантажити», «Відкрити в бібліотеці»; помилка — текст і «Повторити».

### 6.9 Бібліотека
- Видалення файлу: якщо `assets.usage` не порожній — модалка «Файл використано в N проєктах: …. Видалити все одно?».

## 7. Помилки
| Ситуація | Поведінка |
|---|---|
| Порожній таймлайн / видалені / необроблені файли | `renders.start` → `VALIDATION` з переліком кліпів; кліпи підсвічуються |
| Падіння ffmpeg | рендер `failed`, у `error` — хвіст stderr; «Повторити» |
| Таймаут рендеру | `failed` «Рендер перевищив ліміт часу» |
| Невалідний таймлайн у `save` | `VALIDATION` (захист від зламаного клієнта) |
| Конфлікт версії | модалка (6.7) |
| Протухлі URL | `projects.assets` за 5 хв до закінчення; помилка завантаження медіа → одне оновлення URL |
| Кодек не підтримується браузером | заглушка в прев'ю |

## 8. Тестування
- **Unit** (`packages/timeline`, `packages/render`):
  - операції: рух, снепінг, трім у межах джерела, розрізання зв'язаної пари, видалення пари / лише аудіо, перекриття → впритул, `xfade`, округлення до кадру, `setFormat`, `normalizeDoc` для старих документів;
  - `evaluate` (alpha/scale у ключових точках, порядок шарів) і `audioPlan`;
  - закони ефектів: `expr`, обчислений простим інтерпретатором виразів, дорівнює `at` у 11 точках;
  - `compileFfmpeg`: входи, `-ss/-t`, `enable`, `adelay`, `amix`, розмір чернетки, відсутність `zoompan`.
- **Render** (справжній ffmpeg у контейнері, фікстури з `synth`):
  - тривалість через ffprobe = `docDuration` ±1 кадр (final і draft), розмір чернетки 720p;
  - кольори пікселів: проміжок — чорний, кліп — свій колір, середина `fade`/`xfade` — суміш ±10 %, верхня доріжка перекриває нижню;
  - аудіо: тон в інтервалі кліпу, тиша поза ним, `volume: 0` — тиша, видалене зв'язане аудіо — тиша;
  - кадр `drawFrame` (`@napi-rs/canvas`) проти кадру ffmpeg (Ken Burns і zoom на текстурі, 3 моменти): середня абсолютна різниця < поріг (підбирається один раз і фіксується в тесті).
- **Інтеграційні** (API + Postgres + RustFS + ffmpeg): `save`/`CONFLICT`, `asset_ids` і `assets.usage`, ізоляція користувачів, `renders.start` з видаленим/необробленим файлом → `VALIDATION`, повна задача `render` → asset `ready` з мініатюрою, повтор задачі не дублює asset, скасування не лишає asset і тимчасової теки, `asset.analyze` для старого файлу (піки + `has_audio`).
- **E2E** (Playwright, fake-провайдер): новий проєкт 9:16 → перетягнути MP4 з ОС на таймлайн → кліп + хвиля → трім → undo/redo → «Чернетка 720p» → рендер в історії → MP4 у бібліотеці з очікуваною тривалістю; фото з панелі бібліотеки → Ken Burns за замовчуванням → зміна параметра в інспекторі; модалка видалення файлу, що використаний у проєкті.
