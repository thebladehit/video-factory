# Підпроєкт 4 «Конвеєр тема → чернетка» — специфікація

- **Дата:** 2026-10-22
- **Статус:** погоджено в обговоренні, очікує перегляду
- **Базова специфікація:** `docs/specs/2026-10-20-video-factory-design.md` (§1 критерій 1, §4.1 задачі, §6.1 конвеєр, §7 AI, §10 помилки, §12 підпроєкт 4)
- **Попередні підпроєкти:** `docs/specs/2026-10-20-subproject-1-library.md`, `docs/specs/2026-10-20-subproject-2-editor.md` (у `main`), `docs/specs/2026-10-20-subproject-3-voice.md` (усі в `main`)
- **Гілка:** `feat/subproject-4-pipeline` від `main`

## 1. Мета

З однієї теми однією кнопкою отримати **чернетку на таймлайні**: сценарій зі сцен, візуал кожної сцени (з бібліотеки або згенероване фото), озвучку базовою й вибраними мовами з субтитрами, опційну музику. Чернетка відкривається в редакторі, мовні версії доступні одразу (перемикач мов, рендер усіх мов). Після цього все доредаговується в редакторі, студії озвучки або на сторінці сцен, де будь-яку сцену можна перегенерувати.

### Рішення власника (з обговорення)
| Питання | Рішення |
|---|---|
| Взаємодія | **Гібрид:** одна кнопка за замовчуванням, але з перемикачем «Зупинитися після сценарію» (правка тексту сцен перед дорогими кроками). Після завершення є сторінка сцен із перегенерацією кожної сцени (текст, візуал) і «Пересібрати чернетку» |
| Джерело візуалу | **Спершу бібліотека, потім генерація фото.** Автопідстановка з бібліотеки лише за сильного збігу; слабкі збіги — підказки на сторінці сцени. Генерація відео — ручна дія для окремої сцени, не за замовчуванням |
| Мови | **Базова + вибрані мови одразу:** конвеєр перекладає сценарій і озвучує всі мови наявними задачами підпроєкту 3; перед запуском — оцінка вартості |
| Музика | **Опційний трек із бібліотеки**, вибраний у налаштуваннях запуску; кладеться на всю довжину з повтором, тихо, з fade-out |
| Архітектура | **Координатор як стан у БД + дрібні ідемпотентні задачі.** Чиста функція `advance` вирішує, що ставити далі; викликається на події задач і на старті API. Без однієї довгої задачі й без керування з браузера |

### Зв'язок із підпроєктом 3
- Таблиці `scenes` / `scene_texts` із загальної специфікації (§5) **не створюються**: сцена конвеєра = **сегмент** `TimelineDoc.segments`, текст озвучки = `voice_lines` (сегмент × мова). Конвеєр зберігає лише свої метадані сцени (`pipeline_scenes`).
- Переклад і озвучка — наявні задачі `voice.translate` і `voice.synthesize` без змін поведінки; мовні версії будує `localize`. Базовий документ збирається так, що для базової мови темп кожного сегмента ×1.

## 2. Дані (міграція 0006)

**`pipeline_runs`** — один запуск на проєкт:
`id`, `user_id`, `project_id` (unique, cascade), `settings jsonb` (`PipelineSettings`, 2.1), `stage` (`script|review|produce|assemble|done`), `status` (`running|awaiting_review|done|failed|cancelled`), `error text null`, `script_job_id uuid null`, `assemble_job_id uuid null`, `assembled_version int null` (версія документа після останньої збірки), `created_at`, `updated_at`.

**`pipeline_scenes`** — метадані сцени:
`id`, `user_id`, `run_id` (cascade), `segment_id text` (= id сегмента документа; unique `(run_id, segment_id)`), `position int`, `visual_prompt text` (англійською — моделі фото так працюють краще), `keywords text[]` (базовою мовою й англійською, для пошуку в бібліотеці), `visual_asset_id uuid null` (`on delete set null`), `visual_source` (`library|generated|manual`, null — немає), `generation_id uuid null` (генерація фото/відео в роботі; `on delete set null`), `suggestions uuid[]` (до 3 слабких збігів бібліотеки), `status` (`empty|queued|running|ready|failed`), `job_id uuid null`, `error text null`, `updated_at`.

**`voice_lines.text_origin`** + значення `'script'` (текст зі сценарію; поводиться як `manual`: «Перекласти все» його не перезаписує, бо це базова мова).

**Задачі (`JobType`)** + `pipeline.script`, `pipeline.scene`, `pipeline.visual`, `pipeline.assemble`. **`JobSubject`** + `sceneId` (з payload), щоб UI й координатор знали, якої сцени стосується подія.

### 2.1 Налаштування запуску (`packages/shared/src/pipeline.ts`, Zod)
```ts
type PipelineSettings = {
  topic: string;                       // 3–2000 символів
  format: '9:16' | '16:9';
  targetSec: number;                   // 9:16: 15–90 (за замовч. 45); 16:9: 60–900 (за замовч. 300)
  style: string;                       // ≤ 1000 символів; додається до «стилю каналу» з user_settings
  baseLanguage: string;
  languages: string[];                 // включно з базовою; порядок = порядок у UI
  textModel: ModelRef;                 // за замовч. defaults.text
  imageModel: ModelRef;                // за замовч. defaults.image
  voices: Record<string, VoiceChoice>; // голос кожної мови; за замовч. user_settings.voices
  musicAssetId: string | null;         // аудіо з бібліотеки
  stopAfterScript: boolean;            // за замовч.: 16:9 — true, 9:16 — false
};
```

## 3. Координатор (`apps/api/src/modules/pipeline`)

### 3.1 Етапи
1. **`script`** — задача `pipeline.script` (4.1). Записує `pipeline_scenes`, рядки базової мови (`text_origin='script'`) і **документ-скелет**: лише `segments` з оціненою тривалістю, без кліпів (наявні `voice.translate`/`voice.synthesize` працюють лише із сегментами документа). Оцінка = `quantize(LEAD + символи / 15 + TAIL)`, сегменти впритул від 0. Далі: `stopAfterScript` → `review` (`awaiting_review`), інакше → `produce`.
2. **`review`** — користувач править тексти, промпти й ключові слова, додає, видаляє, переставляє сцени (документ-скелет оновлюється разом із `pipeline_scenes`). «Продовжити» → `produce`.
3. **`produce`** — паралельно: `pipeline.visual` на кожну сцену; `voice.synthesize` базової мови (наявний `enqueueSynthesize`); `voice.translate` на кожну іншу мову, після успішного перекладу мови — `voice.synthesize` цієї мови.
4. **`assemble`** — коли кожна сцена в кінцевому стані (`ready|failed`) і кожен рядок мов не `queued|running` (переклад мови теж завершено): задача `pipeline.assemble` (4.3).
5. **`done`** — проєкт стає звичайним проєктом редактора й студії; сторінка сцен лишається для перегенерації.

### 3.2 `advance(state) → Action[]` (чиста функція)
Вхід — знімок запуску: `stage`, `status`, стани сцен, стан задачі сценарію/збірки, стани рядків по мовах і чи перекладено мову (є рядки з текстом для всіх сегментів або задача перекладу завершилась). Вихід — список дій: `enqueueScript`, `toReview`, `enqueueVisual(sceneId)`, `enqueueSynthesize(language)`, `enqueueTranslate(language)`, `linkGeneratedAsset(sceneId)`, `enqueueAssemble`, `markDone`, `markFailed(error)`.
- Сервісна обгортка `runAdvance(deps, runId)` читає знімок, обчислює дії, виконує їх. Кожна дія ідемпотентна й атомарна: сцена забирається умовним `update … where status in (empty, failed) returning` (як `enqueueSynthesize`), етап змінюється `update … where stage = <очікуваний>`. Паралельні виклики `runAdvance` для одного запуску не дублюють задач.
- **Коли викликається:** слухач `queue.onEvent` на кінцеві події задач `pipeline.*`, `voice.translate`, `voice.synthesize`, `image.generate`, `video.generate`, `asset.process`, якщо подія стосується запуску (за `subject.projectId` / `sceneId` / `lineId` / `generationId` / `assetId` через таблиці); на старті API — для всіх запусків зі `status='running'`; після кожної мутації `pipeline.*`.
- **Генерація → сцена:** якщо `generation_id` задано, а `visual_asset_id` ні — береться `generations.asset_ids[0]`, коли генерація `done` (`visual_source='generated'`). Сцена `ready`, коли asset `ready`; `failed` — коли генерація або asset `failed` (текст помилки — з них).

## 4. Кроки

### 4.1 Сценарій (`pipeline.script { projectId }`, `pipeline.scene { sceneId }`)
- `TextGen.generateObject` за Zod-схемою `{ title, scenes: { narration, visualPrompt, keywords: string[] }[] }`. Промпти — `packages/ai/src/prompts/script.ts` з версією (`SCRIPT_PROMPT_VERSION`), мова narration = базова мова.
- **9:16:** хук у першій сцені (перші 1–2 с), сцени 3–8 с, без вступу-привітання; заклик у кінці — лише якщо так велить стиль.
- **16:9:** вступ → розділи → висновок, сцени 8–25 с.
- Кількість сцен ≈ `targetSec / середня довжина` (9:16 — 5 с, 16:9 — 15 с), бюджет слів = `targetSec × 2,5` — обидва в промпті. Стиль каналу (`user_settings.channel_style`) + `settings.style` додаються до system.
- Перевірки результату: 1–60 сцен, `narration` 1–1500 символів (`TTS_MAX_CHARS`), `visualPrompt` непорожній, `keywords` 1–8. Невалідна відповідь → одна повторна спроба з переліком помилок у промпті, далі — помилка задачі.
- **16:9 довше 10 хв** (> 40 сцен) — двома етапами в тій самій задачі: план розділів `{ title, sections: { title, summary, sec }[] }`, потім сцени кожного розділу з контекстом попередніх (останні 3 сцени).
- Назва проєкту = `title`; `projects.topic` = тема. Запис у `generations` (`capability='text'`, `cost_estimate` за токенами).
- Ідемпотентність: якщо сцени запуску вже існують — задача нічого не генерує й лише доводить етап.
- **`pipeline.scene`** — перегенерація тексту однієї сцени з контекстом (тема, попередня й наступна сцени): переписує `visual_prompt`, `keywords` і текст рядка базової мови (`text_origin='script'`). Озвучка цієї сцени стає «застарілою» за наявним механізмом `voiced_hash`; переклади — «застарілими» за `source_hash`. Нічого не перегенеровується автоматично.

### 4.2 Візуал (`pipeline.visual { sceneId }`)
1. Сцена вже має `visual_asset_id` або `generation_id` → нічого (ідемпотентність).
2. **Бібліотека:** `listAssets` (наявний пошук: full-text + trigram) окремо за кожним ключовим словом і за всіма разом, `kind ∈ {image, video}`, `status='ready'`, орієнтація формату (`vertical` для 9:16, `horizontal` для 16:9) або `square`. Кандидат — найкращий за рангом файл, якого не взяла інша сцена цього запуску. **Автопідстановка** лише якщо ранг ≥ `LIBRARY_MATCH_MIN` (константа в коді, підібрана тестом на фікстурі бібліотеки) → `visual_source='library'`, `ready`. Інші топ-3 → `suggestions`.
3. **Генерація фото:** `generateImage` (наявний сервіс: `generations` + `image.generate`) з `settings.imageModel`, `aspect` = формат, `n=1`, prompt = `visual_prompt`; сцена отримує `generation_id`, `running`; asset прив'язує координатор (3.2). Теги asset: тема, «конвеєр», ключові слова (додаються після прив'язки).
4. **Ручні дії** (сторінка сцен): «Згенерувати знову» (очищує `visual_asset_id`/`generation_id`, задача заново, пропускаючи бібліотеку), «Згенерувати відео» (`generateVideo` наявним шляхом; модель і тривалість — у діалозі з оцінкою), «Вибрати з бібліотеки» або підказка (`visual_source='manual'`).

### 4.3 Збірка (`packages/timeline/src/assemble.ts`, чиста)
```ts
assembleTimeline(input: {
  format: VideoFormat; fps: number;
  scenes: { segmentId: string; estimatedSec: number; baseVoiceSec: number | null;
            visual: { assetId: string; kind: 'image' | 'video'; durationSec?: number; width: number; height: number } }[];
  music: { assetId: string; durationSec: number } | null;
}, newId?: () => string): TimelineDoc
```
- Тривалість сцени `D = quantize(LEAD + baseVoiceSec + TAIL)`, якщо базова озвучка готова (тоді `fitSegment(D, V)` дає темп ×1 — для базової мови відео не змінюється), інакше `quantize(estimatedSec)`. Сегменти впритул від 0, на сітці кадрів.
- **Фото:** кліп на весь сегмент + `kenburns` з чергуванням за індексом сцени (наближення 1→1,15 / віддалення 1,15→1; фокус 0,4 / 0,6 по x), детерміновано.
- **Відео:** довше за сцену — початок (`in=0`); коротше — повтор із `in=0`, доки не заповнить сцену (останній шматок обрізаний; шматок < 1 кадру відкидається); `volume=0`, без зв'язаного звуку (у чернетці лише голос і музика).
- `fit='cover'`; відношення сторін файлу відрізняється від формату більш ніж на 20 % (квадрат у 9:16, вертикальне в 16:9) → `contain`.
- Склейки прямі (без `fade`/`xfade`).
- Сцена без візуалу (помилка генерації, видалений файл) отримує **чорну заглушку**: служба підставляє asset «Порожня сцена» (чорний PNG розміру формату, один на користувача й формат, теги «заглушка», «конвеєр»; створюється за потреби одразу `ready`). Кліп потрібен, бо `docDuration` рахується за кліпами: без нього остання сцена обрізала б документ і свій сегмент. Заглушка не має Ken Burns.
- **Музика:** доріжка `music`, кліпи з повтором до кінця документа, `volume=0.15`, `fadeOut=1.5` на останньому кліпі.
- Доріжок озвучки й субтитрів у базовому документі немає — їх додає `localize` для кожної мови (як у підпроєкті 3).

**Задача `pipeline.assemble { projectId }`:** читає сцени, готові рядки базової мови (`duration_ms`), asset-и (тип, тривалість, розмір), музику → `assembleTimeline` → запис документа з перевіркою версії (`select … for update`, `timeline_version + 1`, `asset_ids`), `assembled_version`; `projects.voice`: для кожної мови — голос із `settings.voices` і субтитри увімкнені з пресетом за форматом (9:16 → `preset:shorts`, 16:9 → `preset:classic`); `original.mode='replace'`. Етап → `done`.

### 4.4 Після `done`
- Новий візуал сцени (перегенерація, відео, вибір з бібліотеки) **точково** замінює `assetId` кліпів сегмента: чиста операція `replaceSegmentVisual(doc, segmentId, visual)` (кліпи візуальних доріжок, що лежать усередині сегмента, видаляються, ставиться новий за правилами 4.3 на межі сегмента), версія +1. Сегмента в документі немає (видалено в редакторі) → зміна документа пропускається, сцена позначається «немає в таймлайні».
- «Пересібрати чернетку» (`pipeline.reassemble`) — повна збірка з підтвердженням «Ручні зміни таймлайну буде втрачено» і перевіркою версії (`CONFLICT`).
- Зміна тексту чи голосу після збірки — у студії озвучки; базова озвучка іншої довжини обробляється `localize` (темп/стоп-кадр), документ не перезбирається.

## 5. API (`pipeline.*`, tRPC)

| Процедура | Поведінка |
|---|---|
| `pipeline.estimate(settings)` | `{ usd, parts: { script, images, tts, stt, translate } }`: сценарій — токени за бюджетом слів; фото — верхня межа (кожна сцена генерується); TTS — символи / 15 → хвилини × мови × ціна моделі голосу; `whisper-1` — за хвилинами, якщо TTS без міток; переклад — токени. `null`, якщо в моделі немає ціни |
| `pipeline.start(settings)` | перевірки: модель тексту й фото доступні (є ключ), голос кожної мови вибраний і доступний, мови з конфігу, музика — власний `ready` аудіо-asset; створює проєкт (`title` = перші 80 символів теми до генерації назви, `format`, `topic`, `base_language`, `languages`, порожній документ) і `pipeline_runs`; ставить `pipeline.script`; повертає `{ projectId }` |
| `pipeline.get({ projectId })` | запуск (етап, стан, помилка, налаштування), сцени по `position` (текст базової мови, промпт, ключові слова, візуал з мініатюрою й джерелом, підказки з мініатюрами, стан, помилка, «немає в таймлайні»), стани рядків по мовах (з `getVoice`), лічильники прогресу. Для проєкту без запуску — `NOT_FOUND` |
| `pipeline.updateScene({ sceneId, narration?, visualPrompt?, keywords? })` | будь-коли, крім `script`; `narration` → рядок базової мови (`setText` з `text_origin='script'`) |
| `pipeline.addScene({ projectId, after?, narration })`, `pipeline.deleteScene({ sceneId })`, `pipeline.moveScene({ sceneId, position })` | лише на `review`; документ-скелет перераховується (оцінки тривалості), рядки видаленої сцени лишаються «сиротами», як у підпроєкті 3 |
| `pipeline.continue({ projectId })` | `review` → `produce` |
| `pipeline.regenerateScene({ sceneId, part: 'text' \| 'visual' })` | `pipeline.scene` / `pipeline.visual` (з очищенням візуалу) |
| `pipeline.generateSceneVideo({ sceneId, model, durationSec? })` | `generateVideo` + `generation_id` сцени |
| `pipeline.setSceneVisual({ sceneId, assetId })` | власний `ready` image/video → `visual_source='manual'`; після `done` — `replaceSegmentVisual` |
| `pipeline.reassemble({ projectId, version })` | лише `done`; `version` ≠ поточній → `CONFLICT` |
| `pipeline.cancel({ projectId })` | скасовує задачі запуску (`queued|running`: сценарій, сцени, рядки мов, збірка) → `status='cancelled'`; готове лишається |
| `pipeline.retry({ projectId })` | `failed|cancelled` → `running`; невдалий етап і невдалі сцени/рядки ставляться знову (`advance`) |
| `projects.list` | картка проєкту + `pipeline: { stage, status, done, total } \| null` |

Кожен запит фільтрується за `userId`; чужий id → `NOT_FOUND`.

## 6. Інтерфейс (apps/web)

### 6.1 Діалог «Відео з теми»
Кнопка поруч із «Новий проєкт» на головній (`/`). Поля: тема (textarea), формат 9:16/16:9, тривалість (повзунок у межах формату), стиль (необов'язково), базова мова + мови (чіпи), голос кожної мови (`VoicePicker` з підпроєкту 3, заповнений замовчуваннями), моделі тексту й фото (з `defaults`, лише доступні), музика (пошук аудіо в бібліотеці з прослуховуванням або «без музики»), ☐ «Зупинитися після сценарію». Унизу — оцінка вартості (`pipeline.estimate`, debounce 300 мс) і **«Створити»** → `/projects/$id/pipeline`. Причини неактивної кнопки показуються текстом (немає ключа, не вибрано голос).

### 6.2 `/projects/$id/pipeline` — сторінка сцен
```
┌ назва · тема ▾ · [Скасувати] / [Повторити] · [Відкрити в редакторі] [Студія озвучки] [Пересібрати]  ┐
├ Сценарій ✓ → Перевірка ● → Візуал і озвучка 7/12 → Збірка → Готово      (помилка етапу — тут)    │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 1 ┌мініатюра┐ бібліотека │ UK: текст сцени ✎                       │ ● uk ● en ○ de │ ↻ текст      │
│   └─────────┘ ↻ 🎬 📚    │ промпт: «aerial view of…» ✎ · ключові: …│                │ [видалити]* │
│   підказки: ▫ ▫ ▫        │                                         │                │ ⠿ *         │
│ 2 …                                                                                              │
│ [+ сцена]*                                         [Продовжити]*          (* — лише на «Перевірці») │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```
- Прогрес — наявний `jobs.feed` (події з `sceneId`/`lineId`/`projectId` проєкту → refetch `pipeline.get`, з об'єднанням подій як у студії).
- Текст і промпт редагуються на місці (debounce-збереження); стан озвучки мов — крапки (кольори як у студії); клік → студія на цьому сегменті.
- Після першого переходу в `done`, якщо сторінка відкрита, — автоперехід у редактор.

### 6.3 Редактор і список
- Для проєкту із запуском у редакторі є кнопка «Сцени» → `/projects/$id/pipeline`. Поки запуск не `done`/`cancelled`/`failed` — банер «Конвеєр ще працює» і документ лише для перегляду (як режим мови підпроєкту 3), щоб не конфліктувати зі збіркою.
- Картка проєкту в списку показує етап і прогрес («Візуал і озвучка 7/12»); клік на незавершений проєкт веде на сторінку сцен.

## 7. Помилки
| Ситуація | Поведінка |
|---|---|
| Немає ключа для моделі тексту/фото/голосу або не вибрано голос мови | `pipeline.start` → `MODEL_UNAVAILABLE` / `VALIDATION` до створення проєкту; у діалозі — підказка, кнопка неактивна |
| Сценарій: невалідний об'єкт | одна повторна спроба з переліком помилок, далі запуск `failed` з текстом; «Повторити» |
| Сценарій: контент-політика / ліміт провайдера | без повтору (наявна класифікація `providers/errors.ts`), запуск `failed` з текстом |
| Візуал сцени: помилка | сцена `failed` з текстом, інші йдуть далі; збірка відбувається (сцена — чорна заглушка); «Повторити» на сцені |
| Переклад мови / озвучка рядка: помилка | наявні стани `voice_lines`; збірка не чекає повторів; сцена без базової озвучки має оцінену тривалість |
| Жодної готової базової озвучки | збірка відбувається на оцінках; банер «Озвучка не вдалася — повторіть у студії» |
| Рестарт API посеред запуску | задачі `running` → `failed` (наявне правило); `advance` на старті: невдала задача сценарію/збірки → запуск `failed` («Повторити»); сцени й рядки — звичайні помилки з «Повторити» |
| Скасування | задачі запуску скасовуються; рядки звільняються наявним `releaseOnCancel`, сцени → `empty`; «Повторити» продовжує з того самого місця |
| Документ змінено між збіркою й точковою заміною | заміна працює з актуальною версією; немає сегмента → «немає в таймлайні» |
| «Пересібрати» з застарілою версією | `CONFLICT` → «Таймлайн змінено — оновіть сторінку» |
| Видалено asset візуалу / музики | `on delete set null` → сцена «немає візуалу» (наступна збірка — заглушка); у таймлайні — наявна червона заглушка підпроєкту 2 |

## 8. Тестування
- **Unit:**
  - `assembleTimeline`: тривалість з озвучки й з оцінки, сітка кадрів, сегменти впритул; фото з Ken Burns і чергуванням; відео довше/коротше (повтор, відкинутий шматок < кадру); `contain` для чужої орієнтації; сцена із заглушкою (остання сцена-заглушка не скорочує документ); музика (повтор, обрізка, `fadeOut`, гучність); **`localize(assembleTimeline(…), база)` дає `speed=1`, `hold=0` у кожному сегменті з озвучкою**;
  - `replaceSegmentVisual`: заміна фото на відео й навпаки, кліпи інших сегментів не змінюються, сегмента немає → документ без змін;
  - `advance`: таблиця «знімок → дії» для кожного етапу, `review`, переклад → озвучка мови, генерація → прив'язка asset, помилки сцен і рядків, скасування, повтор, повторний виклик без нових дій;
  - схема й промпт сценарію (кількість сцен і бюджет слів для 9:16 / 16:9, стиль каналу в system, двоетапний режим > 40 сцен), перевірка результату; `estimate`; вибір збігу бібліотеки (поріг, без повторів між сценами, орієнтація).
- **Інтеграційні** (FakeProvider, Postgres, RustFS):
  - `start` → `script` → `produce` → `assemble` → `done`: документ із сегментами й кліпами, рядки uk+en `ready`, `projects.voice` з голосами й субтитрами, музика; `voice.localized` для `en` працює; `renders.start({ language: 'en' })` → MP4;
  - `stopAfterScript` → `updateScene`/`addScene`/`deleteScene`/`moveScene` → `continue`;
  - сильний збіг бібліотеки підставляється, слабкі → `suggestions`, один файл не йде у дві сцени;
  - помилка однієї сцени (fake-провайдер, що падає на маркері в промпті) не блокує збірку;
  - рестарт посеред `produce` (зупинка й новий старт runtime) → запуск доходить до `done`;
  - `regenerateScene('visual')` і `setSceneVisual` після `done` точково міняють кліп; `reassemble` з конфліктом версії;
  - `cancel` і `retry`; паралельні `runAdvance` не дублюють задач; ізоляція користувачів.
- **E2E** (Playwright, fake): «Відео з теми» → 9:16, uk+en, без зупинки → сторінка сцен із прогресом → автоперехід у редактор → таймлайн має кліпи сцен, перемикач EN показує доріжку озвучки → рендер EN → MP4 у бібліотеці. Другий: 16:9 зі «Зупинитися після сценарію» → правка тексту сцени → «Продовжити» → «Готово» → «Відкрити в редакторі».
- **Live** (`pnpm test:live`): сценарій справжніми моделями (Anthropic, OpenAI, Google) за схемою — валідний об'єкт, кількість слів у межах ±30 % бюджету.

## 9. Поза обсягом
Генерація й автопідбір музики; переходи між сценами; семантичний пошук (pgvector); кілька кадрів (B-roll) на сцену; кілька голосів/персонажів; аватари; автоматична генерація відео для всіх сцен; публікація й метадані для платформ (підпроєкт 5).

## 10. Готово, коли
- З теми однією кнопкою (без зупинки) виходить чернетка в редакторі: сцени з візуалом (з бібліотеки або згенероване фото), озвучка базовою мовою з темпом ×1, мовні версії вибраних мов із субтитрами, опційна музика; рендер кожної мови дає MP4.
- Зі «Зупинитися після сценарію» сценарій правиться до дорогих кроків, «Продовжити» доводить до чернетки.
- Будь-яку сцену можна перегенерувати (текст, фото, відео, вибір з бібліотеки) після збірки; візуал у таймлайні змінюється точково, «Пересібрати» — з підтвердженням.
- Помилка однієї сцени чи мови не зупиняє конвеєр; рестарт API не губить запуск; скасування й повтор працюють.
- `pnpm test` (unit, int, render) і `pnpm --filter @vf/web e2e` проходять; `pnpm typecheck && pnpm lint` чисті.
